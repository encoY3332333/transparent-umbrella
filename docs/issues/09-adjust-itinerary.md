# [Feature] 行程局部调整

## 背景 / Background

自动生成的行程一定不会百分百合意——问卷 Q9 显示 71.9% 的用户想「换掉某个不想去的景点」，59.4% 想「调整先后顺序」。但调整不能破坏可行性：把需要 90 分钟通勤的景点拖到上午，系统必须立刻告诉他时间不够。

对应 SRS：3.3.5 · 用例 UC-05

## 需求描述 / Description

支持拖拽调序、替换活动、增删活动、锁定必去项后重排；每次调整在副本上执行并实时重校验，确认后才覆盖原方案并生成新版本。

## 任务清单 / Tasks

- [ ] 页面：时间轴拖拽（HTMX `sortable` 扩展，**改不动就退回上移/下移按钮**，见 ADR-007 待验证假设 1）
- [ ] 页面：每个活动卡片右侧「替换 / 删除 / 锁定」三个图标按钮（`hx-put` 提交，`hx-target` 指向所在日的时间轴片段）
- [ ] 页面：顶部实时校验结果条（绿：无冲突 / 橙：超预算 X 元 / 红：存在时间冲突），由 preview 接口返回的片段替换
- [ ] 页面：撤销（Ctrl+Z）与重做（Ctrl+Shift+Z），用 Alpine.js 维护最近 5 步操作栈
- [ ] 后端：`PUT /api/itineraries/{id}/adjust` 接收操作类型 + 参数，返回新版本
- [ ] 后端：在行程副本上应用变更，只重算受影响活动相邻两项的通勤（BR-15）
- [ ] 后端：`revalidate()` 重新执行可行性校验，返回冲突清单
- [ ] 后端：版本管理——每次确认保存 version+1，历史最多保留 10 个（BR-14），超出淘汰最早
- [ ] 后端：并发修改检测（最后保存为准 + 返回冲突提示）
- [ ] 测试：`tests/test_adjust.py` 覆盖拖序、替换、删除、锁定重排、并发冲突、版本淘汰

## 验收标准 / Acceptance Criteria

- [ ] AC-1 单次拖拽调序后 1.5 秒内完成重算与重新渲染
- [ ] AC-2 任意调整后行程仍满足 BR-06 至 BR-09；若无法满足，必须显式给出冲突说明与快捷修复按钮
- [ ] AC-3 支持撤销最近 5 步，撤销后行程与操作前完全一致
- [ ] 被标记「锁定」的活动，在重排中位置不变
- [ ] 调整后超预算时，顶部显示超出金额并提供「查看降本建议」
- [ ] 调整后违反天气约束时，提示「该时段有暴雨，是否改期或替换为室内活动」
- [ ] 出现并发修改时，以最后保存为准并提示「检测到其他窗口的修改」
- [ ] 行程历史版本最多 10 个，第 11 次保存后最早的版本被淘汰
