# [Feature] 规划反馈

## 背景 / Background

推荐策略的权重目前是问卷推出来的初始值（w_cost=0.28 等），没有真实数据校准。反馈功能是这套参数后续能自我迭代的唯一入口——每次反馈都记录当时的策略参数快照，才能做归因分析（哪个版本的参数让满意度下降）。

对应 SRS：3.3.7 · 用例 UC-07

## 需求描述 / Description

对已查看的行程提交满意度评分、问题类型标签与文字反馈，保存策略参数版本快照。

## 任务清单 / Tasks

- [ ] 后端：`POST /api/itineraries/{id}/feedback` 写入反馈
- [ ] 后端：满意度必填校验（1–5 星）、文字长度 0–500 字（BR-19）、敏感词校验
- [ ] 后端：问题类型标签从固定集合选择（BR-20）：排程不合理 / 时间冲突 / 预算不准 / 景点不合适 / 通勤过远 / 其他
- [ ] 后端：保存当时的 `StrategyParameter.version` 快照，用于归因分析
- [ ] 后端：同一行程 24 小时内重复提交按「覆盖更新」处理，不重复计分
- [ ] 页面：`templates/feedback/form.html` 星级评分 + 标签多选 + 文本框（带字数统计，字符数用 Alpine.js 实时显示）
- [ ] 前端：未选满意度时提交按钮禁用
- [ ] 测试：`FeedbackServiceTest` 覆盖必填校验、字数边界、敏感词、快照保存、24 小时覆盖

## 验收标准 / Acceptance Criteria

- [ ] AC-1 提交后 1 秒内返回成功提示
- [ ] AC-2 反馈记录中保存了当次行程使用的策略参数版本号
- [ ] AC-3 满意度为空时提交按钮禁用
- [ ] 文字超过 500 字时输入框禁止继续输入并显示 `500/500`
- [ ] 文字含敏感词时提示修改并高亮命中词
- [ ] 同一行程 24 小时内第二次提交只更新原记录，不新增
- [ ] 反馈记录关联行程编号、游客编号、策略版本号三者
