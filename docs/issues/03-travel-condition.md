# [Feature] 出行条件录入与校验

## 背景 / Background

出行条件是整个排程的输入。条件错了，后面全错——「出发日期填成昨天」「预算填 200 块想去三亚 5 天」「目的地输入错别字解析不出来」这三类问题必须在录入阶段就拦掉，否则排程引擎会白白消耗外部接口配额（BR-10 限制单次 60 次）。

对应 SRS：3.3.2 · 用例 UC-02

## 需求描述 / Description

实现出行条件录入表单，页面轻量校验 + 服务端权威校验双重把关；通过后完成地名解析与行程期内天气预报摘要，解锁「生成行程」按钮。

## 任务清单 / Tasks

- [ ] 页面：`templates/condition/form.html`，三组字段（去哪里 / 怎么玩 / 花多少），出发地默认取上次使用城市
- [ ] 页面：本地校验（必填、日期先后、金额范围、人数范围），错误直接标红不发起请求
- [ ] 页面：预算滑块（500–200000 元）+ 精确输入框双向绑定
- [ ] 后端：`POST /api/conditions/validate` 返回校验结果 + 地名解析坐标 + 天气摘要
- [ ] 后端：`ConditionValidator` 校验天数 ∈ [1,15]（BR-03）、预算 ∈ [500,200000]（BR-04）、人数 ∈ [1,20]（BR-05）
- [ ] 后端：`MapServerAdapter.geocode()`，解析失败时返回候选地名列表（最多 5 个）
- [ ] 后端：`WeatherServerAdapter.getForecast()`，超出预报窗口时标注「远期天气仅供参考」
- [ ] 后端：预算低于目的地保底花费时返回 warning 而非 error（允许继续，标记「预算紧张」）
- [ ] 测试：`tests/test_condition_validator.py` 覆盖 12 个边界用例

## 验收标准 / Acceptance Criteria

- [ ] AC-1 所有必填项为空时，「生成行程」按钮保持禁用
- [ ] AC-2 输入非法日期（结束早于开始）时，表单内标红提示，且网络面板中无请求发出
- [ ] AC-3 校验通过后 2 秒内完成地名解析与天气查询并回显摘要
- [ ] 出发日期早于当天：提示「出发日期不能早于今天」，禁止提交
- [ ] 天数 > 15：提示「暂仅支持 15 天以内的规划」，禁止提交
- [ ] 地名解析失败：展示候选地名列表供选择，或允许在地图上手动选点
- [ ] 天气服务不可用：仍允许提交，天气字段展示「未知」，并在提交时不阻塞
- [ ] 表单数据在页面刷新后可从 sessionStorage 恢复（避免误刷新丢输入）
