# Release v0.1.0 — 需求基线 + 工程规范

**发布日期**：2026-11-11
**类型**：正式发布（非预发布）
**Tag**：`v0.1.0`

---

## 这次发布包含什么

从 `v0.0.1` 的「只有协作骨架」推进到「需求基线冻结 + 后端工程基线可运行 + 协作链路实跑一轮」。
这一版**仍然没有可交付的业务功能**，交付的是「第一阶段（需求阶段）的完整过程材料」和「下一阶段能直接开写的工程底座」。

### 新增

**工程基线（`backend/`）**

- FastAPI + Jinja2 + HTMX 单体骨架，5 层结构（`api` / `services` / `engine` / `adapters` / `models`），共 1105 行。
- `backend/tests/` — 45 个 pytest 用例，覆盖路由注册、模板渲染、排程引擎权重计算、错误码一致性。
- `pyproject.toml` + Ruff + Mypy，CI 中可通过。
- 容器化：`docker-compose.yml` 与 `Dockerfile` 可本地起服务。

**协作实跑**

- 18 个 PR（12 个已合并、1 个关闭、5 个待评审），39 次 CI 运行。
- 14 个 Issue 全部创建并指派（A 5 / B 5 / C 4），1 个已关闭（#1 脚手架）。
- 三人都真实走过「开分支 → 提交 → 开 PR → CI → 合并」的链路。

**文档增补**

- `docs/srs/智能旅游规划系统-软件需求规格说明书-v1.0.docx` — 与教师模板 5 章 + 附录对齐，14 张 UML 图已嵌入。
- `docs/guides/` — 附件 3 协作规范、附件 4 需求获取材料。
- `docs/adr/ADR-007-switch-to-python-stack.md` — 技术栈由 Java + Vue 切换为纯 Python 的决策记录。
- `docs/assessment-checklist.md` — A1–A8 / B1–B7 逐项自查，随版本更新到 2026-11-12 的真实状态。
- `docs/reports/第1组第1次项目进展报告-20261112.docx` — 第 1 次进展报告定稿版。

### 变更

- 技术栈统一为 Python（FastAPI / Jinja2 / HTMX / SQLAlchemy），撤销 Spring Boot + Vue 3 方案，影响架构文档与 14 个 Issue 的技术备注。
- `docs/releases/` 命名统一为 `docs/release-notes/`。

### 已知限制

1. **业务功能未开始**：14 个 Issue 只关闭 1 个，P0 的 UC-01–UC-04 仍在开发。
2. **分支保护未开启**：`main` 目前允许直推和自评自合，需仓库所有者在 Settings → Rules 中配置。
3. **首轮 12 个已合并 PR 无第三方评审**：事后补评论无效，改为在 #29–#33 上做真实交叉评审。
4. **测试覆盖率 42%**，覆盖率门禁（`--cov-fail-under=40`）尚在 PR #33 中未合并。
5. **CI 有 2 个红灯 PR**（#32 排程引擎、#33 覆盖率门禁），合并前需修复。
