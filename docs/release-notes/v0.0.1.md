# Release v0.0.1 — 项目奠基

**发布日期**：2026-11-09
**类型**：预发布（Pre-release）
**Tag**：`v0.0.1`

## 这次发布包含什么

仓库从「只有一个 README 的空壳」变为**可协作的工程骨架**。这一版**没有可运行的业务代码**，它交付的是「让三个人能在同一套规则下并行开发」的基础设施。

### 新增

**协作配置**

- `.github/workflows/ci.yml` — 四段式 CI：`backend` / `frontend` / `lint-repo` / `ci-summary`。当前后端与前端目录尚不存在，通过 `guard` 步骤探测 `pom.xml` / `package.json` 是否存在，不存在则输出 `::notice::` 并跳过。**这是为了让文档类 PR 能先合进来**；#1 落地后自动转为真实执行，无需改 CI。
- `.github/ISSUE_TEMPLATE/feature.md`、`bug.md` — Issue 模板，含「对应 SRS 章节与用例编号」字段，强制需求可追溯。
- `.github/pull_request_template.md` — 7 小节，含「AI 辅助说明」与 7 项自查清单。
- `.github/CODEOWNERS` — 路径负责人映射，`* @encoY3332333` 兜底。
- `.github/BRANCH_PROTECTION.md` — 组长手动操作手册，含分支保护 9 项对照表、10 个 Labels、5 个 Milestone、14 个 Issue 的三种创建方式。

**工程文件**

- `CONTRIBUTING.md` — 9 章协作规范，含 6 条硬性约束与本项目的 Commit scope 约定。
- `README.md` — 项目介绍、差异化定位、9 功能表、技术栈选型理由、快速开始、目录结构、团队分工。
- `CHANGELOG.md` — Keep a Changelog 格式。
- `.gitignore` — 分区注释，含「环境变量与密钥」专区。
- `.env.example` — 全部配置项的占位说明，含排程引擎五项权重与外部调用预算。
- `LICENSE` — MIT。

**文档**

- `docs/srs/` — 需求基线 V1.0（docx）+ 基线管理说明。
- `docs/architecture.md` — 三层架构、模块划分与 5 条分层约束、行程生成/调整两条主链路数据流、8 张核心表、非功能设计要点、降级策略表。
- `docs/api.md` — 9 个用例的完整接口契约、统一响应体、39 个错误码。
- `docs/adr/` — 6 份架构决策记录（JWT / 排程拆分 / 贪心算法 / 服务端代理 / 副本调整 / 统计拥挤度）。
- `docs/issues/` — 14 个 Issue 的完整正文，含任务清单、可验证验收标准、依赖关系。
- `docs/meetings/` — 前两次会议纪要（md + docx 双份）。
- `docs/contributions/` — 个人工程贡献说明书模板与自查表。
- `docs/guides/` — 协作规范、需求获取问卷与访谈提纲。

## 为什么发这个版本

课程考核 A8「发布与答辩」要求有可追溯的版本节点。这一版的价值不在代码，而在**它是后续所有 PR 的起点**：

- 从这一版开始，`main` 受保护，任何人不能直推
- 从这一版开始，每个 PR 都会被 CI 检查
- 从这一版开始，「什么时候定的规矩」有 commit 时间戳可查
