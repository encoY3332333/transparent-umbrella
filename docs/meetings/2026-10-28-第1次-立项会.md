## 一、议程

| 2 | 项目选题与边界 | 备选三个方向：校园二手交易、智能旅游规划、考研复习助手。从「可演示、有外部数据依赖、模块可切分」三个角度比较。 | 选定「智能旅游规划系统（SmartTrip）」。范围收敛为：天气 + 人流量 + 活动三个约束的行程自动编排；明确砍掉「社交拼单」与「语音播报」两项，理由：前者涉及多人协同的账号体系，工作量不可控；后者对核心闭环无增益。 | 全组 |

| 7 | 阶段计划 | 4 周内要交付什么。 | 第 1 周：立项、需求获取设计；第 2 周：问卷与访谈执行、竞品分析；第 3 周：SRS 分头撰写；第 4 周：评审、定稿、Issue 拆分、提交第 1 次进展报告。 | 全组 |

## 六、后续变更说明（2026-11-10 补记，不改动上文原始记录）

本次会议「议题 5 技术选型」的结论是 **Vue 3 + Vite + TypeScript / Spring Boot 3 + Java 17 / MySQL 8**。

该结论已于 2026-11-10 被推翻：全组在实际准备脚手架时发现「对 Java 更熟」这一判断不成立（无人配置过 Spring Boot 多环境与 Maven 多模块，第一个 Issue 即卡在 `pom.xml` 依赖冲突上），且四台机器的 JDK + Maven + Node + MySQL 组合各不相同，README 在组外实测失败两次。

技术栈已整体切换为 **Python 3.11 + FastAPI + Jinja2/HTMX + SQLAlchemy 2.0**，完整决策过程（含被否决的「维持 Java」「Python 后端 + Vue 前端」「Django」三个方案）见 [ADR-007](../adr/ADR-007-switch-to-python-stack.md)。

**为什么保留上文的原始结论而不直接改掉**：会议纪要是过程证据，篡改会让「决策演进」这条线索消失，答辩时反而无法解释为什么 L1 阶段说 Java、L2 阶段是 Python。保留原文 + 补记变更，是更经得起追问的做法。
