# 第 1 章 引言

## 1.1 编写目的

本册说明"校园智办 / SmartTrip"**怎么实现**：系统被拆成哪些模块、模块之间怎么协作、数据怎么落库、接口长什么样、关键决策为什么这么定、怎么部署运维。

它回答的是 SRS 没有回答的问题。SRS 定"要做什么、做到什么算合格"，本册定"用什么结构、凭什么结构能撑住那些验收条件"。两份文档的分工是：

| 文档 | 回答 | 读者 |
|---|---|---|
| SRS（附件 4） | 系统要满足哪些需求、每条需求怎么验收 | 甲方 / 评审老师 / 测试 |
| SDD（本册） | 系统由哪些部件组成、部件如何协作、为什么这样组成 | 开发 / 编码评审 / 答辩质询 |

**本册不重述需求**。凡涉及"为什么需要这个功能"，一律指向 SRS 的用例编号（UC-xx）与业务规则编号（BR-xx），避免两份文档各说一套、日后修订不同步——第 1 阶段报告已经因为"数字口径不一致"被扣过分。

## 1.2 范围

本册覆盖 `backend/app/` 全部代码与 `docs/` 下的设计资产，对应 9 个用例：

- UC-01 登录与偏好建档、UC-02 出行条件录入与校验、UC-03 行程生成
- UC-04 行程查看、UC-05 行程调整、UC-06 保存与分享
- UC-07 规划反馈、UC-08 POI 维护、UC-09 策略参数配置

**不在本册范围**：需求本身（见 SRS）、测试用例与测试结果（见第 2 次报告第 4 节）、答辩材料。

## 1.4 术语与缩略语

| 术语 | 含义 |
|---|---|
| UC-xx | 用例编号，与 SRS 第 4 章一致 |
| BR-xx | 业务规则编号，与 SRS 第 3 章一致 |
| POI | Point of Interest，可游玩的兴趣点 |
| CrowdIndex | 拥挤度指数，取值 0–100，越高越拥挤 |

| SDD | 本册，Software Design Description |

## 1.6 文档结构

第 2 章给全景（分层、模块、数据流）；第 3、4 章分别落到模块与接口；第 5 章落到表结构；第 6 章交代 7 个关键决策及其代价；第 7 章是跨模块的横切关注点（缓存、配额、事务、异常、安全）；第 8 章是部署与运维；附录 A 是需求到设计的追踪矩阵，用于答辩时"这条需求你在哪实现的"这类追问。

## 1.7 编写与维护约定

- **每章必须写"实现状态"**：`已实现` / `部分实现` / `仅设计`。本册初稿时（2026-11-26）系统的真实完成度见附录 A，不得夸大。
- **图与代码同源**：图在 `docs/diagrams/` 入库，图内每个类/表/接口旁标注源文件路径。
- **修订留痕**：任何一章修改都在该章末尾与 `README.md` 修订记录里同一天登记，包含修订人代号。
- **数字必须有出处**：涉及性能、容量、次数的数字，要么指向配置文件（如 `strategy_w_cost`），要么写测量前提，不接受"经验值"。
